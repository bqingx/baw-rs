# Changelog

Version numbers track `Cargo.toml`. Verification evidence for a version lives in
`verification/` and is regenerated by `scripts/verify.sh`; anything under
`verification/v0.2.0-historical/` describes a different tree and is not evidence for
the current source.

## Unreleased

- **Flattened wallet model (breaking).** The wallet name is now a global flag:
  `baw-rs --wallet alice wallet balance` instead of `baw-rs vaults --registry R run alice -- wallet balance`.
  Wallet lifecycle is owned by the binary (`wallets add|remove|list|status|serve|stop`), which never
  requires `--wallet`; `task` moved to the top level (`--wallet alice task arm sell-1 --confirm`).
  The registry defaults to `$BAW_RS_REGISTRY`, else `$HOME/wallets/registry`, overridable by global
  `--registry`. A wallet-scoped command without `--wallet` and without the legacy `--wallet-dir` pair
  now fails with an error naming the flag. `vaults`, `vaults run NAME --`, `vaults register`,
  `vaults task NAME`, `--wallet-dir`/`--instance-id-file`, `serve` and `--warm` remain supported as
  documented compatibility paths. Leaf commands stay at 45.

- **Trimmed command surface (breaking).** Removed the `prediction`, `defi`, `x402-payment`,
  `tracker`, `signal`, `leaderboard`, `limit-order`, `fast` and `batch` families together with
  their source modules, tests and reference docs. Leaf commands drop from 116 to 45 (root CLI
  33, plus `vaults` and `openfour`). Kept: `auth`, `wallet`, `market-order`, `contract-call`,
  `sign-message`, `approvals`, `openfour`, `vaults` (incl. `task`), `cli-check`, `skill-check`,
  and the single-wallet `serve` / `--warm` machinery. `uint256` parsing moved from `fast.rs` to
  `src/uint.rs`; `openfour encode-buy` keeps its offline encoder.

- Repo published under the MIT license (`LICENSE`), and absolute build-host paths inside
  `verification/` normalised to `<repo>` / `<scratch>` / `<home>` before the repo went public.
  Only path text changed; counts, exit codes and binary hashes are untouched. See
  `verification/README.md` and `docs/PARITY-IMPL-NOTES.md`.

- `BAW_RS_CONCURRENT_WRITES=1` skips the local exclusive write lock, for diagnosing backend
  behaviour. Measured: two simultaneous writes from one wallet always yield one
  `BROADCASTED` and one `Binance API code 351716`, so a single wallet is serialised by
  Binance itself. Not a throughput switch; see `docs/SIGNING.md`.

- Added `openfour quote-buy`: reads the Open Four bonding curve and builds the
  `buyByBudget` transaction in-process — no Node, no wallet session, no local simulation.
  Measured 67-74 ms against 467-1100 ms for the reference script, with byte-identical
  calldata, amounts and slippage floor on the same inputs. See `docs/OPENFOUR-QUOTE.md`.

- Added `--skip-prechecks` / `BAW_RS_SKIP_PRECHECKS=1`: skip the developer-mode and
  wallet-address reads before a guarded write and trust `--from` (which becomes mandatory).
  Saves the two measured reads (0.51-0.54 s + 0.43-0.64 s per call) at the cost of the only
  local guard against sending from a wallet other than the one named. Off by default.

- Added `contract-call fire`: preview then execute in a single process, with `--confirm` and
  a unique `--operation-id` but no policy file and no human digest review. The preview's
  risks and authority changes are returned so the caller can log them.
- The two pre-write backend reads (developer mode, wallet addresses) are now reused for
  `BAW_RS_CHECK_TTL_MS` inside a resident server (default 3000 ms there, 0 in one-shot
  commands), so a preview and the execute that follows it pay for them once. The cache is
  per wallet client and dropped on any session change.

- Added `--instance-id-file PATH`: read the instance identity from a private 0600 file
  instead of the command line, so the passphrase stays out of `ps` and shell history. Same
  string ⇒ same key, so existing wallets keep working with no re-login; supplying both
  `--instance-id` and the file is an error. The file is refused unless it is a 0600,
  owner-only, single-link regular file (no symlinks, ≤ 4 KiB).

Ownership changes after the 0.2.2 drop was reviewed and rebuilt independently.

- Added `docs/SESSION-LIFECYCLE.md`: how the login state is generated, stored, read,
  used on the wire, and invalidated, with the known gaps listed there.

- Added `scripts/verify.sh`: one command regenerates fmt / clippy / test / release-build
  logs, `source-sha256.json` (now tagged with the git commit and a `dirty_source` flag)
  and `release-identity.txt`.
- Added `scripts/source_manifest.py` and `scripts/leaf_commands.py`. The command
  inventory is now generated from the built binary instead of hand-maintained.
- Quarantined the shipped v0.2.0 logs and manifest under
  `verification/v0.2.0-historical/`, with a note recording why they do not cover this
  tree (9/19 hashes mismatch, log version 0.2.0 vs manifest 0.2.2, no shipped binary).
- README: documented that `--instance-id` is a passphrase-derived key, i.e. a
  credential with fail-closed loss/recovery behaviour, not a machine identity.
- README: stated that no prebuilt binary ships, and that `verification/leaf-commands.txt`
  is the authoritative command list (26 leaves: 24 commands + `batch` + `serve`).
- INTEGRATION-REPORT.md: marked as a v0.2.0 historical document.

## 0.3.0 — full command parity with `baw` 1.12.0

The crate now exposes every leaf the installed JavaScript CLI exposes, except
`tracker ws` (WebSocket transport, needs a client dependency — see "Known gaps").

- New families, each with its own clap enum, wire calls mined from the installed bundle
  and unit tests: `approvals`, `limit-order`, `prediction`, `defi`, `x402-payment`,
  `tracker`, `signal`, `leaderboard`, `cli-check`, `skill-check`, plus
  `wallet speed-up|cancel|resolve-domain`.
- Every endpoint literal in the tree was checked against the installed
  `@binance/agentic-wallet` bundle; no path exists in the port that is not in the bundle.
- Mutation classification (`is_mutation` + `mutation_payload`) is defined per leaf for
  every family, so `--confirm` + a unique `--operation-id` is mandatory exactly on the
  writing leaves, and the journal input is deterministic and credential-free.
- `docs/JS-CLI-PARITY.md`: verbatim `--help` of every reference leaf, generated from the
  installed CLI; `verification/leaf-commands.txt`: the authoritative list for this crate,
  generated from the built binary.
- Fixed a clap name/alias collision on `wallet cancel` that panicked every debug-mode CLI
  parse.

Known gaps, stated rather than papered over:

- Some response shapes are passed through untouched because the minified bundle does not
  reveal their fields (tracker monitor rows, leaderboard presets, prediction defaults);
  each is commented in-file.
- No live wallet operation has been performed: no QR signin, signature, swap, transfer or
  DeFi position. Offline tests use loopback fixtures only.

`tracker ws` is implemented as of this release: pre-subscribe (`/ws/pre-subscribe`,
`bizKey: WALLET_TRACKER`) then a WebSocket to `/w3w/stream` with `SUBSCRIBE`, 30s `PING`,
`UNSUBSCRIBE` on `--duration`, and 5s→120s reconnect backoff when no duration is set. It
adds `tokio-tungstenite` + `futures-util` as dependencies.
