# Task 热路径：本轮优化与测量边界

最新的三次调用模式见 [THREE-CALL.md](THREE-CALL.md)，已真实验收一次：钱包执行阶段 949.95 ms，币安请求 2、辅助状态读取 0。上一版同边界为 1419.88 ms；单次对比不是稳定提速保证或完整事件到上链耗时。

## 已优化

### 1. 有界状态读集

准备阶段、其他 Task 动作及保留原策略的路径使用命令级读集，合并重复的 settings、trading-limit、钱包列表、网络列表及特定链 tx-lock-status 读取。新 Task OKX swap 的触发路径改用绑定的准备记录，根本不调用这些读取。

- 默认/最大年龄 3 秒；`BAW_RS_CHECK_TTL_MS=0` 禁用缓存，更小正值按较小窗口执行。
- 只命中明确只读接口；preview/execute/授权等写 POST 永不缓存。
- 不是服务端原子快照，也不跨等待期无限信任准备状态。过期仍需读取新状态，不做等待期间的高频后台轮询。
- 可以利用仍在窗口内的地址/设置缓存，但保留原时间，不因复用而延长年龄。
- 钱包各有独立读集；会话替换、Cookie 轮换、失效会清空旧值。缓存命中也检查取消、截止及身份绑定。
- 其他路径仍可能刷新状态；新 OKX Task 的提交路径只允许三次核心 HTTP，辅助读取即使命中缓存也拒绝，不会退回现场刷新。WSS 事件/回执校验另算。

### 2. 复用 OKX HTTP 传输

同一钱包的 Client 保存 OKX 传输，准备、报价和触发执行共享同一连接池。凭据每次私有加载并按请求签名，不固定在默认 Header、Cookie jar 或跨钱包全局对象中。

连接池每主机最多保留一个空闲连接，客户端空闲上限 600 秒，无主动保活请求、代理、重定向或隐式重试。服务端可以提前关闭连接，因此复用是尽力而为，不承诺永远零 TLS 握手。Alchemy 仍由独立的实例级单 WSS actor 管理，不改变其连接限制。

本地路由校验改为纯校验，不再为了 validate_response 构造另一套 HTTP client、重读 OKX 凭据。

### 3. 编译式计划

arm/显式 resume 时，为固定配置全部动作编译类型化计划，绑定钱包对象、身份指纹和不同的准备/兑换操作 ID。触发后不再解析 CLI argv 或重新查 registry 解析钱包。

编译命令不复制原始身份口令，只引用原本的钱包对象；钱包仍按既有设计保存必要会话/身份状态。计划仅驻留内存、不写入状态 JSON；恢复先验证身份与原截止，再从固定定义重新编译。运行时仍检查目录、会话、配置绑定、显式许可及必要资金条件，不以编译为由跳过授权。

这是提前编译未来步骤，不是提前授权未来步骤；额度仍在各步自己的监听前准备。

### 4. 合并安全落盘

触发标记与动作 InFlight admission 在同一次原子持久保存中提交，之后才允许执行动作。保留提交前日志、防重和一次性预览绑定；不是删除关键 fsync。无提交可能发生在 admission 保存之前。

## 连接复用观测

最新构建增加 `hotPathTiming.httpTransport`：OKX swap、币安 Preview/Execute 的池/socket 不透明编号、协议、区间连接活动及建连合计。DNS/TCP/TLS 不独立拆分，也不能相减得到服务端耗时；见 [HTTP-CONNECTIONS.md](HTTP-CONNECTIONS.md)。观测版随后已实盘验收一次：钱包阶段 1013.15 ms，三个调用均无新连接尝试，Preview/Execute 同一 socket。仍不能倒推之前 949.95 ms 样本，也不能把 HTTP 等待全归于服务端计算。

## 事件至执行的本地时序

本轮在触发/钱包结果增加 `triggerTiming`，细分 WSS actor 取帧、消费/缓冲、规范块读取的锁/限流/交换、准入持久化、worker 调度、钱包排队/会话准备、dispatch、核心 HTTP 及结果保存。不添加请求或计时专用落盘；历史回补/恢复缺少原始通知时填 null，不把本地时序冒充链上事件到成交。该版仅离线验证、未切后台，见 [EVENT-TIMING.md](EVENT-TIMING.md)。

## 本地观测字段

Task 的成功对象结果提供：

- `stateReadStats.binanceRequests`：命令内实际发起的币安 HTTP 请求尝试数，包括策略与 preview/execute，不包括 OKX/RPC。
- `policyReads`：其中属于白名单状态读取的尝试数。
- `cacheHits`：在取消/绑定校验通过后，实际复用的缓存读取次数；不等于精确节约的 TCP 请求数。
- `maxAgeMs`：本次读集年龄上限。新三次调用模式为 0，表示只计数且不允许状态查询，并不代表强制刷新。
- `walletExecuteMs`：工作线程内钱包队列等待、会话/日志、SDK 调用至返回的本地总时间；不包括事件接收、规范块校验及 admission 落盘。

OKX 结果提供 `hotPathTiming`：

- `routeFetchMs`：OKX swap 构造请求至响应体/JSON 完成。
- `routeValidationMs`：取得构造后、调用币安 preview 前的本地校验。
- `previewCallMs`：SDK preview 调用，可能包含过期状态刷新、网络与预览落盘。
- `executeCallMs`：SDK execute 调用，包含绑定消费、可能的策略刷新和网络响应。
- `beforeExecuteCallMs`：perform_swap 开始到调用 SDK execute 之前，不是实际 POST 发出时间。
- `buildThroughResponseMs`：perform_swap 开始至 execute 调用返回，不含更早的发送方解析/准备记录检查。

上述均为本机单调时钟测量，不是服务端处理耗时、事件到广播的完整时延、链上 Gas 或成交确认耗时。错误早退可能没有全部字段。不要把 mock 耗时当作生产延迟。

## 验证

新回归验证：读集去重、到期/零 TTL、错误不缓存、写请求不缓存、会话/Cookie 隔离、缓存命中仍检查取消与绑定、真实回环 TCP 保持同一连接并轮换请求密钥、校验不再读取凭据，以及编译计划拒绝其他钱包/控制命令/skip 标志。

现有 controller 测试还验证：订阅前已授权、触发后没有授权 RPC、恢复不重发、不续期、临时编译计划不落盘，并在首次 swap 请求前检查磁盘已有 triggered 和 InFlight。

最新三次调用版已真实观测到 949.95 ms 钱包执行阶段，前一版同边界 1419.88 ms 且含五项状态读取；完整事件到广播/上链延迟仍未测量。未实现全流水线累计额度预授权，也未取消必要 preview。新的准备记录有效性由原 Task gate、模式原到期时间和本地身份/配置绑定约束，不是无限缓存或保证后台状态不变。
