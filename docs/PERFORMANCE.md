# 性能验证边界与本地基准

以下为当前服务器上的 release 测试产物、纯内存流水线状态管理基准。没有登录态、网络请求、磁盘 fsync 或真实交易，**不能解释为触发到提交/成交的延迟**。

## 可复现命令

```sh
CARGO_BUILD_JOBS=1 cargo test --locked --release --lib \
  local_pipeline_bookkeeping_benchmark -- --ignored --nocapture
```

每个步骤两个钱包，模拟实际使用的 snapshot 复制、claim、Submitted/Confirmed 更新，统计整条流水线的本地记账时间。

## 同机优化前后（2026-11-05）

| 场景 | 样本 | 优化前 p50 | 优化后 p50 |
|---|---:|---:|---:|
| 3 个 task / 6 个动作 | 1000 | 24.587 μs | 11.963 μs |
| 256 个 task / 512 个动作 | 30 | 269.629 ms | 117.149 ms |

优化只移除了 live 状态更新中重复的拓扑校验、集合构造和额外恢复快照复制。创建/加载仍完整校验配置；live 路径仍核对进度形状与步骤顺序，不省略钱包、授权或提交检查。

优化后 p95 分别为 12.147 μs / 122.911 ms。大流水线仍有整张 snapshot 的复制成本，不宣称 O(1) 更新。

原始本机日志：`/tmp/baw-pipeline-benchmark.log`、`/tmp/baw-pipeline-benchmark-after.log`；不是远端生产证据或发行版性能保证。

## 已由离线集成测试覆盖

- 不同钱包执行互不阻塞；同钱包串行。
- 指定三步重叠钱包集合共 6 次 mock 执行。
- 真实本地 WS 上订阅与只读 RPC 共用一个 socket，相同订阅/短时读取合并，断线不静默重连。
- 已确认动作在 reconcile/resume 后不重复，原截止时间不延长。
