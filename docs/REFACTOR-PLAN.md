## Implemented

- Instance-owned multi-wallet tasks/pipelines: overlapping wallet membership, parallel members, sequential completion gates, explicit time/block/log triggers.
- One lazy shared WSS actor for RPC replies, reference-counted newHeads/logs subscriptions, task receipts and named-daemon OKX auto-approval. Endpoint exclusion, bounded buffers, read coalescing and no HTTP fallback.
- Event startup backfill pages at most 10 blocks per request for Alchemy Free, with a 500-block total bound, per-page cancellation/deadline checks, canonical validation and no loss of buffered live notifications. RPC rejections identify method/numeric code without forwarding arbitrary provider text.
- OKX-only quote/swap; original Binance quote/swap implementation removed. Task allowances are now checked and, only with explicit consent, exactly granted before listening. Preparation waits for the first bound successful receipt, without extra two-confirmation/state rereads. Triggered swaps cannot read/repair/wait for allowances. Standalone swap policy is unchanged.
- Separate preparation/swap journals, bound readiness records, a fixed maximum 120-second preparation budget and a later listening budget preserve duplicate/deadline protection. RUNNING can still be preparing; results.phase=WAITING denotes listener readiness. Future steps prepare before their own listeners, not by merged speculative grants.
- Contract preview/execute/fire paths retained.
- Private durable progress and pre-submit claims; confirmed completion checks hash, wallet sender, canonical block and confirmation depth.
- Explicit `pipeline reconcile`: reads execution/operation-journal hashes and chain evidence only; absence never becomes permission to retry.
- Explicit `pipeline resume --confirm`: only Pending actions execute, original deadlines are preserved, previously admitted triggers do not retrigger. Unresolved/reverted, expired, cancelled or legacy unbound state refuses continuation.
- Arm captures wallet directory/session/identity fingerprints; backend request boundaries and resume recheck them. Different login state cannot inherit an existing task's consent.
- Removed `native_shared.rs`, the entire wallet-local logs/pending/block-time engine, old typed executor/IPC, and obsolete dedicated clients/tests. Wallets no longer carry per-wallet task books/listeners/reservations. Ordinary cold/warm directory access, login/session handling and per-wallet execution queues remain.
- `task` aliases `pipeline`, not a separate command family or engine. Old wallet selectors and retired protocol frames reject; current workflow and recovery tests remain.
- Optimized live in-memory state updates by avoiding repeated immutable topology validation and a redundant snapshot clone. Full validation remains at creation/restore.
- Compiled in-memory plans bind all fixed actions at arm/resume; triggers avoid CLI parsing and wallet-name resolution. Per-wallet OKX HTTP pools survive preparation/trigger, credentials remain per-request, and local route checks no longer construct an HTTP client or reload secrets.
- New Task OKX swaps bind a pre-listening wallet policy to the complete arguments/profile and original task gates. Triggered execution permits exactly one fresh OKX swap, one Binance Preview and one Execute; nested SDK code must not query auxiliary state or even consume its cache. Backend rejection, App confirmation and unknown execution pause without refresh/repair/retry. This counts core HTTP, not WSS event canonicalization or receipt confirmation. See docs/THREE-CALL.md.
- Preparation and other paths retain command-local read sets with a hard 3-second maximum (0 disables), session/Cookie invalidation, no cached writes and normal binding checks. Prepared swap scopes use counters only and do not re-enable reads at 0 TTL. New receipt records provide the original sender without extra wallet APIs, even after mode expiry.
- Trigger and InFlight claims share one durable admission save before execution. Request counts and scoped local timing fields are described in docs/HOT-PATH.md; no new production-latency result is claimed.
