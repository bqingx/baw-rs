# 错误、未知结果与对账

1. 同时检查退出码、JSON success、data的业务状态；退出0或HTTP200不能单独证明成交。
   资金签名/执行若只返回未知结构，应归为未知，保留恢复标识，不编造成功。
2. CLI错误原文在移除秘密后报告。可以明确区分“本地参数/锁失败”与“收到后端错误”；
   没有文档/对照实测就不猜错误码含义，尤其不能将351716直接等价为nonce锁或永久串行限制。
3. UNCERTAIN / FAILED_OR_UNKNOWN / timeout / 连接断开：停止自动重发，查操作日志、tx-lock、pending/all历史、
   对应orderId/txHash和链上receipt/余额变化。旧ID永不复用；**新ID也不保证不会重复交易**。
4. 若明确拒绝发生在广播之前，可以在确认意图仍有效、重新获取报价/预览并获得所需授权后决定重试；
   不能仅凭“不见txHash”断言没扣钱。
5. Receipt 0x1证明执行成功；仍核对实际收到数量及手续费。0x0说明上链失败，通常仍有gas，不能算零成本。
6. 并发/时延测试报告逐笔请求阶段、原始状态、txHash、回执；少量样本不能推导20%成功率或固定吞吐上限。
7. 报盈亏时列买入本金、实际卖出回款、买卖及授权gas；用链上整数计算，说明价格换算时间/来源。
   整个钱包余额差只有排除同期其他转入转出后才能当本轮盈亏。不把估计数伪装精确成本。
8. auth过期、权限不符、错误identity直接停止。禁止删/覆盖session、修改加密算法或换钱包“兜底”。

业务读取也可能输出敏感字段：对外只展示必要的公开地址、状态、orderId/txHash等，不输出会话标识和签名秘密。
